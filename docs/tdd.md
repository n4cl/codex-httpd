# TDD ルール

実装タスクは TDD をデフォルトとします。Kent Beck の TDD サイクルに従って進めます。

## RED - 失敗するテストを書く
- 次の小さな機能単位のテストを書く
- テストは失敗する状態で始める（実装はまだない）
- 目的が伝わるテスト名にする

## GREEN - 最小限のコードを書く
- そのテストを通す最小の実装にする
- このテストだけを通すことに集中する
- 先回りした設計・実装はしない

## REFACTOR - 整理する
- 重複をなくし、読みやすさを上げる
- 必要に応じて設計改善を行う
- 変更後もすべてのテストが通ること

## VERIFY - 品質を確認する
- format → lint → test を実行する
- 新旧すべてのテストが通る
- 既存機能に退行がない
- カバレッジは維持または改善する
